Intégrez l’encaissement VitPay à votre site ou à votre logiciel · API v1 · mise à jour le 20 novembre 2026

VitPay vous donne une seule API pour encaisser vos clients par carte : demandes de paiement, page de paiement hébergée, webhooks signés, remboursements et reçus. Les paiements sont exécutés par votre propre compte chez un prestataire de paiement agréé, qui vous verse directement les fonds.

Phase pilote : seul le mode test est ouvert. Les clés réelles seront proposées à l’ouverture des paiements réels. Demander un accès développeur.

1. Démarrage rapide

  1. Dans Business → Paramètres, connectez votre compte de test chez votre prestataire de paiement.
  2. Dans Business → Développeurs, notez l’identifiant de votre organisation et créez une clé Test (vp_sk_test_…). Elle n’est affichée qu’une fois.
  3. Créez une demande de paiement, puis redirigez votre client vers payUrl.
  4. Recevez la confirmation par webhook payment.succeeded, puis livrez ou activez le service.
Adresse de l’API (staging)https://api.staging.vitpay-ma.com
Adresse de l’API (production)communiquée à l’ouverture des paiements réels
FormatJSON, montants en chaîne décimale ("149.90"), dates ISO 8601 UTC
Spécificationopenapi.json (OpenAPI 3.0), à importer dans Postman, Insomnia ou un générateur de client

2. Clés API, mode test et réel

Authorization: Bearer vp_sk_test_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
CléDemandes crééesCe que la clé peut lire
vp_sk_test_…Test (sandbox), aucun débit réelUniquement les demandes de test
vp_sk_live_…Réelles, sur votre compte prestataire réelUniquement les demandes réelles
  • Pour passer en réel, vous changez seulement la clé : le code reste le même.
  • Une demande de l’autre mode répond 404.
  • Chaque clé a des périmètres : requests:create, requests:read, requests:cancel, refunds:create. N’accordez que le nécessaire.
  • Une clé s’utilise côté serveur uniquement, jamais dans un navigateur ni une application mobile. Révoquez-la immédiatement en cas de fuite.

3. Créer une demande de paiement

curl -X POST "https://api.staging.vitpay-ma.com/v1/orgs/$ORG_ID/payment-requests" \
  -H "Authorization: Bearer $VITPAY_SECRET_KEY" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: facture-INV-2026-0042" \
  -d '{
    "amount": "199.00",
    "currency": "MAD",
    "description": "Abonnement Pro – décembre",
    "merchantReference": "INV-2026-0042",
    "customerEmail": "client@exemple.ma",
    "successUrl": "https://app.exemple.ma/facturation/merci",
    "cancelUrl": "https://app.exemple.ma/facturation",
    "metadata": { "invoiceId": "INV-2026-0042", "customerId": "cus_81" }
  }'

La réponse 201 contient notamment id, reference, status: "open", mode et payUrl. Redirigez votre client vers cette adresse, ou affichez-la en QR code (GET …/payment-requests/{id}/qr.svg).

ChampRôle
amountObligatoire. Chaîne décimale, jamais un nombre flottant.
merchantReferenceVotre n° de commande ou de facture, unique dans votre organisation.
successUrl, cancelUrlRetour du client sur votre site (voir section 4).
customerEmailVisible par vous seulement, jamais sur la page de paiement.
metadataJusqu’à 20 paires clé/valeur texte, renvoyées dans les webhooks.
expiresInHoursDurée de validité du lien, de 1 à 720 heures.

4. Retour du client sur votre site

Après un paiement confirmé, le client est renvoyé automatiquement vers successUrl. S’il abandonne, ou si la demande a expiré ou été annulée, il peut revenir vers cancelUrl. VitPay ajoute à l’adresse :

https://app.exemple.ma/facturation/merci?vitpay_request_id=…&vitpay_reference=VP-…&vitpay_status=paid

Ces paramètres sont indicatifs : n’importe qui peut saisir cette adresse. N’activez jamais un service sur la seule foi de l’URL de retour. Confirmez avec le webhook, ou relisez la demande avec GET …/payment-requests/{vitpay_request_id} et vérifiez status: "paid".

Règles : adresse absolue en HTTPS, sans identifiants (user:pass@) ni fragment (#), 2048 caractères au plus.

5. Webhooks

Dans Business → Développeurs → Webhooks, ajoutez une adresse HTTPS et choisissez les événements : payment.succeeded, payment.failed, refund.succeeded, refund.failed, dispute.opened, dispute.won, dispute.lost. Le secret de signature whsec_… n’est affiché qu’une fois.

POST /webhooks/vitpay
Content-Type: application/json
VitPay-Event-Id: evt_123
VitPay-Signature: t=1763700000,v1=5f2b…

{"id":"evt_123","type":"payment.succeeded","created":"2026-11-20T09:00:00.000Z","livemode":false,
 "data":{"objectType":"payment_attempt","objectId":"…","requestId":"…","merchantReference":"INV-2026-0042",
         "metadata":{"invoiceId":"INV-2026-0042"},"amount":{"amount":"19900","currency":"MAD"}}}

Vérifier la signature. Elle se vérifie sur le corps brut, avant tout parsing JSON. La signature v1 est le HMAC-SHA256, en hexadécimal, de t + "." + corps, calculé avec votre secret. Pendant un changement de secret, l’en-tête contient plusieurs v1 : une seule doit correspondre.

import crypto from 'node:crypto';

export function verifyVitpay(rawBody, header, secret, toleranceSec = 300) {
  const parts = header.split(',').map((p) => p.split('='));
  const t = parts.find(([k]) => k === 't')?.[1];
  const signatures = parts.filter(([k]) => k === 'v1').map(([, v]) => v);
  if (!t || Math.abs(Date.now() / 1000 - Number(t)) > toleranceSec) return false; // anti-rejeu
  const expected = crypto.createHmac('sha256', secret).update(`${t}.${rawBody}`).digest();
  return signatures.some((v1) => {
    const got = Buffer.from(v1, 'hex');
    return got.length === expected.length && crypto.timingSafeEqual(expected, got);
  });
}
  • Répondez 2xx rapidement, puis traitez le message de façon asynchrone.
  • La livraison est garantie au moins une fois : dédupliquez sur VitPay-Event-Id.
  • livemode indique un paiement réel. Ignorez les événements de test dans votre environnement de production.
  • En cas d’échec, VitPay réessaie avec un délai croissant, jusqu’à 10 tentatives. Les redirections ne sont pas suivies.
  • Le bouton Tester envoie un événement test.

6. Kit Node.js

Le kit @vitpay/node (Node 18 ou plus récent, sans dépendance) gère l’authentification, l’idempotence, les nouvelles tentatives, les erreurs typées et la vérification des webhooks. Il est fourni aux intégrateurs pilotes pendant la phase pilote.

import { VitPay } from '@vitpay/node';

const vitpay = new VitPay({
  apiKey: process.env.VITPAY_SECRET_KEY,
  orgId: process.env.VITPAY_ORG_ID,
  baseUrl: 'https://api.staging.vitpay-ma.com',
});

// Encaisser une facture
const r = await vitpay.paymentRequests.create(
  { amount: '199.00', merchantReference: invoice.number, successUrl, cancelUrl, metadata: { invoiceId: invoice.id } },
  { idempotencyKey: `facture-${invoice.id}` },
);
res.redirect(303, r.payUrl);

// Webhook (corps brut, par ex. express.raw({ type: 'application/json' }))
const event = vitpay.webhooks.constructEvent(req.body, req.headers['vitpay-signature'], process.env.VITPAY_WEBHOOK_SECRET);
if (event.type === 'payment.succeeded') await markInvoicePaid(event.data.metadata.invoiceId, event.id);

7. Tester vos paiements

Avec une clé de test, aucun montant réel n’est débité.

  • Prestataire simulé (staging) : la page de paiement propose des boutons pour obtenir un paiement accepté, refusé, abandonné, en attente ou avec authentification 3-D Secure.
  • YouCan Pay en mode test : utilisez les cartes de test du prestataire.

8. Idempotence et nouvelles tentatives

  • L’en-tête Idempotency-Key (8 à 128 caractères A-Z a-z 0-9 _ - : .) est obligatoire pour créer une demande ou un remboursement.
  • Rejouer la même requête avec la même clé renvoie la même réponse, avec l’en-tête Idempotent-Replayed: true. En cas de coupure réseau, réessayez donc sans risque de doublon.
  • Choisissez une clé stable de votre côté, par exemple facture-INV-2026-0042.
  • La même clé avec un corps différent répond 422.

9. Erreurs
